# نظام إدارة الشركة اللوجستية

نظام داخلي لإدارة **الموظفين** (مشرف، مسؤول صيانة، مناديب توصيل) و**أسطول السيارات** و**الشحنات اليومية والرواتب والحوافز** و**المصروفات الشهرية والأرباح واسترداد رأس المال**.

> المرحلة الحالية: نسخة تجريبية محلية للعرض على صاحب المصلحة. البيانات محفوظة في متصفح المستخدم (localStorage).
> بعد الاعتماد: رفع المشروع إلى GitHub وربطه بـ Supabase.

## التشغيل

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # نسخة إنتاج في dist/
```

الدخول تجريبي باختيار الدور: المالك / المشرف / مسؤول الصيانة.

## الوحدات

| الشاشة | المحتوى |
|---|---|
| لوحة التحكم | مؤشرات الشهر، تنبيهات الوثائق والصيانة المستحقة، أداء المناديب، توزيع المصروفات |
| الموظفون | البيانات، الوثائق وتواريخ انتهائها، العهدة، سجل الشحنات والحوافز، حافز خاص لمندوب |
| السيارات | الشراء والتمويل (نقد/أقساط)، الوثائق، العهدة (تسليم/استلام)، الصيانة، الوقود، الحوادث، التكاليف، البيع/التشطيب |
| الصيانة والتشغيل | الصيانة المجدولة (كم/أيام)، سجل الصيانة، الوقود، الحوادث والمخالفات لكل الأسطول |
| الشحنات | إدخال يومي أو إجمالي شهري لكل مندوب + جدول شهري (مندوب × يوم) |
| مسيّر الرواتب | أساسي + بدلات + حافز (ما يزيد عن الحد × قيمة الشحنة) + إضافات − خصومات، مع الاعتماد والتثبيت |
| المصروفات الشهرية | قائمة موحّدة: يدوية + متكررة + تلقائية (رواتب، صيانة، وقود، حوادث)، حسب الفئة، أقساط السيارات |
| الأرباح واسترداد رأس المال | الإيرادات − المصروفات − نسبة استرداد رأس المال = صافي الربح؛ إقفال الشهر يرحّل المبلغ إلى حساب منفصل |
| التقارير | العمالة والسيارات (بفلاتر النوع والحالة والفترة...)، الشحنات والحوافز، أداء 6 أشهر، المصروفات، الأرباح، الوثائق |
| الإعدادات | قواعد الحافز بتاريخ سريان، القوائم المرنة، استرداد رأس المال، أيام التنبيه، النسخ الاحتياطي |
| سجل العمليات | من أضاف/عدّل/حذف ومتى |

## قرارات صاحب المصلحة المطبّقة

- الشحنات تُدخل **يومياً** لكل مندوب.
- الحافز على ما **يزيد** عن الحد (من الشحنة 1001) — الحد والقيمة قابلان للتعديل بتاريخ سريان، ويمكن تخصيصهما لمندوب.
- **لا** حد أدنى، و**لا** احتساب بالتناسب للملتحق خلال الشهر.
- كل السيارات **مملوكة للشركة**.
- المخالفات والحوادث **لا تُخصم** من المندوب؛ تُسجَّل مصروفاً على الشركة.
- المندوب **لا يدخل** النظام.
- عند تسجيل كل إيراد تُحدَّد نسبة منه لاسترداد رأس المال (تتغير شهرياً)؛ تُستقطع من الأرباح وتُرحَّل لحساب منفصل عند إقفال الشهر.
- القوائم مرنة: أنواع العمالة، الوثائق، أنواع الصيانة والحوادث، طرق الدفع — تُضاف من النماذج مباشرة أو من الإعدادات.
- الشحنات تُدخل يومياً أو كإجمالي شهري لكل مندوب.

## النشر

- **الموقع:** https://logmnalsfran-del.github.io/logmnalsfran/ — يُبنى ويُنشر تلقائياً مع كل رفع إلى `main` (`.github/workflows/deploy.yml`).
- **أسرار المستودع المطلوبة:** `SUPABASE_URL` و `SUPABASE_ANON_KEY`.
- **إبقاء نشط:** `.github/workflows/keepalive.yml` كل 3 أيام — يمنع إيقاف مشروع Supabase المجاني، ويحدّث المستودع كل ~45 يوماً حتى لا تتعطل المهام المجدولة.

## الربط بـ Supabase

1. في مشروع Supabase: **SQL Editor ← New query** والصق مخطط قاعدة البيانات `supabase/schema.sql` (محفوظ لدى المسؤول خارج المستودع) ثم **Run**.
   ينشئ 21 جدولاً مع العلاقات، وسياسات الوصول (RLS) لكل دور، وحماية الأشهر المقفلة، والفئات والإعدادات الافتراضية.
2. انسخ `.env.example` إلى `.env` وضع **Project URL** و**Publishable key** من *Project Settings ← API*.
3. شغّل التطبيق وأنشئ أول حساب — يصبح **المالك** تلقائياً — ثم أضف بقية المستخدمين من شاشة «المستخدمون».
4. (اختياري) من الإعدادات: «تحميل بيانات تجريبية للعرض» أو «استيراد من ملف» لنقل بيانات النسخة المحلية.

بدون ملف `.env` يعمل التطبيق في **الوضع التجريبي المحلي** (localStorage) للتطوير.

| الدور | الصلاحيات |
|---|---|
| المالك | كل شيء، ويرى وحده الرواتب والمصروفات والأرباح وسجل العمليات |
| المشرف | الموظفون (دون الرواتب)، الشحنات اليومية، عهدة السيارات |
| مسؤول الصيانة | السيارات، الصيانة، الوقود، الحوادث |

الصلاحيات مطبّقة في قاعدة البيانات نفسها (RLS)، والبيانات المالية للموظفين في جدول مستقل `employee_compensation` لا يقرؤه إلا المالك.
